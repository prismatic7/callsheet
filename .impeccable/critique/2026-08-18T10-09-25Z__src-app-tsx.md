## Design Specificity Verdict

**LLM assessment:** High. The colour grammar (five seed activity types with pastel fills + accent borders), the ghost-card agent layer, and the single quiet column are authored for this product — a day-board that holds, never pings. Nothing here is category-interchangeable with a generic todo app: no progress bars, no streaks, no badges, no timeline. The "A quiet day. No cards yet." empty state is on-voice.

**Deterministic scan:** 1 finding — `layout-transition` on sidebar `width` (App.css:341). Known, documented advisory from phase 4 (one-shot collapse; sanctioned in TASK.md/PIPELINE.md).

**Visual overlays:** Not available — browser injection requires Chrome remote-debugging approval (harness blocked). Fallback: curl HTTP 200 on localhost:1420; index.html served with stock title.

## Overall Impression

The bones are right and the voice is right. The colour grammar is executed exactly per DESIGN.md, the keyboard grammar is a genuine power-user gift, and the ghost cards embody "presence not pressure". The gaps are polish-level: delete is unguarded, errors leak raw text, the window title still says "Tauri + React + Typescript", and the keyboard grammar is invisible to anyone who doesn't read the spec.

## What's Working

1. **Colour grammar executed faithfully** — five seed types with exact HSL tokens, accent borders derived at 70% lightness, custom-type allocator with enforced uniqueness. The detector confirms no drift.
2. **Keyboard grammar is genuinely excellent** — Tab/Shift+Tab navigation, Cmd+Shift+Up/Down reorder, Enter edit, Esc save+blur, Cmd+C/V/X clipboard, Cmd+Left/Right day nav. Alex the power user is served.
3. **Ghost cards embody the product philosophy** — faint dashed-border proposals at the bottom, click to commit, never ping. The agent layer is designed as presence, not pressure.

## Priority Issues

- **[P1] Delete is unguarded** — Backspace on a selected card deletes instantly (Card.tsx:99-102), no confirmation, no undo. A mis-tap loses a card permanently.
  - *Why it matters*: The day's plan is the product's data. Accidental loss violates the calm trust the app promises.
  - *Fix*: Undo (snapshot last deleted card, Cmd+Z restores) or a soft confirm. Undo is more on-voice than a modal.
  - *Suggested command*: /impeccable harden
- **[P1] Error banner leaks raw `String(e)`** — App.tsx:414-416 renders the raw error string. Technical jargon, no recovery path.
  - *Why it matters*: Jordan sees "Error: rusqlite error..." and has no next step.
  - *Fix*: Map known errors to calm copy ("Couldn't save this card. It's still here — try again."), keep details in a log.
  - *Suggested command*: /impeccable clarify
- **[P2] Window title is stock** — index.html:7 still says "Tauri + React + Typescript" with vite.svg favicon. tauri.conf.json is correct ("callsheet") but the webview title leaks the template.
  - *Why it matters*: Brand leak in the most visible place — the window title bar.
  - *Fix*: `<title>callsheet</title>`, replace favicon or drop it.
  - *Suggested command*: /impeccable polish
- **[P2] Hard-coded HSL values not tokenised** — App.css has ~15 hard-coded HSL values (selection, focus-visible, hover states, caret, ghost hover, template hover, day-pane--over) outside the `:root` token block.
  - *Why it matters*: Drift risk — the detector can't distinguish intentional from accidental, and future edits will diverge.
  - *Fix*: Promote to custom properties (`--accent-focus`, `--ghost-hover`, etc.) in `:root`.
  - *Suggested command*: /impeccable extract
- **[P2] Keyboard grammar is invisible** — no hint, no help, no first-run affordance. The grammar is excellent but undiscoverable.
  - *Why it matters*: Jordan never learns Tab/Cmd+Shift+Up/Down; the power-user investment is wasted on everyone who doesn't read the spec.
  - *Fix*: A quiet "?" affordance or a one-line hint in the empty state ("Tab to move between cards · Cmd+Shift+↑↓ to reorder").
  - *Suggested command*: /impeccable onboard
- **[P3] Sidebar width transition** — App.css:341 animates `width` (detector finding). One-shot collapse; layout thrash on a 220px element is minor but flagged.
  - *Fix*: `grid-template-columns` animation or accept as documented.
  - *Suggested command*: /impeccable optimize
- **[P3] Ghost-card label contrast** — `.ghost-card__label` at 11px uppercase, `hsl(0,0%,55%)` on paper ≈ 3.2:1 — below 4.5:1 for small text.
  - *Fix*: Darken to ~40% lightness.
  - *Suggested command*: /impeccable audit

## Persona Red Flags

**Alex (Power User)**: Served well — full keyboard grammar, drag-drop, clipboard. Red flags: no bulk selection (one card at a time), no undo, reorder persists N sequential saves (visible lag on long days).

**Jordan (First-Timer)**: "A quiet day. No cards yet." is clear, but there is no visible "add card" affordance — the only paths are dragging a template (sidebar may be collapsed) or Cmd+V. Keyboard grammar is entirely invisible. Will not discover reorder or ghost cards.

**Sam (Accessibility)**: Cards are `role=listitem` in `role=list`, focus-visible outline present, aria-labels on nav/toggle/grab, reduced-motion respected. Red flags: ghost-card label contrast, raw error text, drag-drop has a keyboard alternative (good) but it is undiscoverable.

## Minor Observations

- `canGoPrev`/`canGoNext` are hard-coded `true` (App.tsx:406-407) — the disabled style exists but never fires.
- `dangerouslySetInnerHTML` is safe (markdown escapes HTML — test proves it) but deserves a comment for future maintainers.
- `persistOrder` fires N sequential `saveCard` calls on reorder — fine for a day's cards, worth a batch command later.
- Empty state is genuinely good copy.

## Questions to Consider

- What if the first-run empty state taught the keyboard grammar instead of just saying "no cards yet"?
- What if delete were undoable (Cmd+Z) instead of confirmed — which is more on-voice?
- What would a confident version of the error state look like — one that holds the user's work while explaining?
